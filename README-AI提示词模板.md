# 组员 AI 修改提示词模板

> 每个组员把自己要改的需求，套进下面的模板发给 AI（CodeBuddy / Cursor 等）即可。
> 模板已写好项目背景、约束和验证步骤，AI 照着做就不会改乱。

---

```

源码在 frontend/ 目录，项目根目录有 AGENTS.md，请先阅读并严格遵守。

我的任务：〔在这里写你要改什么，越具体越好〕

要求：
1. 只改与任务相关的代码，最小改动；
2. 改完告诉我：改了哪些文件、各改了什么；
3. 教我运行 npm run dev 验证效果。
```

## 组员 AI 协作纪律（重要）

1. **先拉再改**：动手前先 `git pull origin main`，拿到最新代码再让 AI 改（否则合并必冲突）。
2. **一次一个任务**：每轮只让 AI 做一件事，做完验证、提交，再做下一件。不要一口气让 AI 改十个需求。
3. **小范围分工**：尽量让每人只负责一类文件（事件数据 / 样式 / 动画），从源头避免撞车。
4. **AI 说改完了 ≠ 真没问题**：必须自己 `npm run dev` 看一眼效果、`npm run build` 确认无报错，再提交。
5. **提交信息写清楚**：commit 写"改了什么"，负责人审核合并时一目了然。
6. **不满意就回滚**：AI 改坏了不要让它继续"修补"，直接 `git checkout -- 文件` 还原，重新描述需求再来一次。

## 合并流程（不变）

改好 → 验证 → 建分支提交 → push → 发起 Pull Request → 负责人审核合并 → 网站自动更新。
